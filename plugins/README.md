# Vendored plugin dialects

These folders are **vendored copies** of the Gherkin dialect definitions from the
canonical plugin repos (OpenTestBed org):

| Folder | Canonical source | What it is |
|---|---|---|
| `fhir-validator/dialect/` | `itb-plugin-fhir-validator/dialect/` | FHIR steps: validate against profile, generate test data, transform, FHIRPath |
| `hcert-decoder/dialect/` | `itb-plugin-hcert-decoder/dialect/` | HCERT steps: decode QR, verify COSE signature, SHLink/VHL flows (+ scriptlets) |

Each `dialect-server.conf` is the nginx config that serves the dialect at the
well-known **`/gherkin-dialect/`** path with CORS, so the authoring app
(itb-plugin-authoring, a static browser app) can load the language extension
**from this running deployment** — the language you author against is exactly
what these deployed services understand.

Endpoints once the stack is up (see `docker-compose.override.yml`):

- FHIR validator dialect:  `http://localhost:8090/gherkin-dialect/component.yml`
- HCERT decoder dialect:   `http://localhost:8091/gherkin-dialect/component.yml`

Add them in the authoring app via the Language overlay → dialect sources
(or `?dialects=http://localhost:8090,http://localhost:8091`).

**Do not edit these files here.** The plugin repos are the source of truth;
re-copy from them when they change (same rule as the authoring app's bundled
copies, which are generated by `itb-cli/src/sync-dialects.mjs`).
